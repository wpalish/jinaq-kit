# JinaqKit

Оригинальная ограниченная версия0.1 по направлению reference12 Make. Опубликованный рецепт синтетического комплекта → проверка всех компонентов → атомарный локальный количественный журнал. Это самостоятельный сценарий, не Make или интеграция.

Все количества — целые штуки без дробей, весов, конверсий или денег. Admin создаёт компоненты с уникальным кодом и названием, рецепт с обоими авторскими описаниями RU/KK и1–10 разными компонентами, расход1–1000 штук на комплект. Черновик может быть неполным. Публикация фиксирует версию, описания, код/название/расход каждого компонента, сортировку по коду; повтор версии запрещён даже после архива. Изменение карточки компонента не меняет версию рецепта или прежний снимок: для нового снимка надо содержательно изменить рецепт/строку. Полных промежуточных черновиков нет.

Admin явно записывает положительное поступление1–1000000 штук с основанием. Staff выбирает опубликованный рецепт и1–100 комплектов. Preview не резервирует и не пишет. Явная команда в одной BEGIN IMMEDIATE транзакции сравнивает общую revision, заново вычисляет остатки и все потребности. Если хотя бы одного компонента не хватает, сохраняется shortage с полным before/needed/after и перечнем нехваток, без единого списания. Успех assembled списывает все потребности целиком. Отказ тоже расходует UUID; повторить можно только новым ключом/командой. Клиент не назначает исход/остатки/снимок/время/автора/порядок. Остатки вычисляются из всех неизменных поступлений, успешных сборок и возвратов; архив не вычитает операции. У компонентов нет ручного поля остатка.

Admin может один раз явно вернуть все компоненты успешной сборки по её исходному снимку с основанием. Это отдельная неизменная запись, не удаление/редактирование/физический возврат/возмещение денег. Нельзя вернуть shortage, часть сборки, вернуть возврат, отменить поступление или повторно списать старую сборку. Staff не делает поступления/возвраты. Успешную невозвращённую сборку нельзя скрыть архивом; после возврата можно, shortage можно. Поступление/возврат можно архивировать только как видимость: количества остаются. Архив компонента/рецепта/публикации закрывает новые поступления/публикации/сборки по ним, прежний возврат остаётся возможен даже по архивным компонентам. Архивный компонент с возвращённым остатком виден в общей сводке. Архив строки рецепта увеличивает его версию. Связь строки с рецептом/компонентом неизменна; заменить — архивировать и создать новую.

Общая revision конфликтует даже при несвязанной правке. Новый UUID requestKey глобален для поступления/сборки/возврата; повтор отвергается даже после архива с новой revision. Общая последовательность seq1..N, серверные автор/время и exact before/after проверяются при восстановлении. Откат часов до последней операции журнала запрещает следующую количественную операцию. Согласованный JSON можно восстановить только в пустую область. JSON/hash не подписаны, согласованность не подлинность/исторические права. Accounts/auth/audit не экспортируются; полную SQLite резервировать согласованно отдельно. HTTPJSON2МБ; большие копии могут превысить лимит. Все сотрудники читают общую область, tenant-изоляции нет. HTTPpreview/hash необязателен и не человеческое одобрение. Нет UI сброса пароля/отзыва сессий.

Нет физического склада, учёта произведённых комплектов как нового SKU, резерва, заказа, доставки, оплаты, внешней записи, Make-кода/коннекторов, AI/cron/webhook/секретов или настоящих данных. Нет подтверждённых клиентов/спроса/экономии. В отличие от QorStock это изменяемый локальный количественный журнал; в отличие от TazaBatch — расход компонентов по рецепту, а не преобразование таблиц.

Operate: унаследовать собственный Shared Work Cabinet TazaBatch navy/pale-blue/green и native формы/таблицы/disclosures. На первом экране сборки видны сохранённый исход, версия, комплектов, автор и текущий возврат; затем таблица всех компонентов before/needed/after и явная admin-форма полного возврата. Текущие остатки показывать отдельно от исторических. Авторские RU/KK тексты имеют lang, интерфейс ru. Поручение автономно продолжать100 определяет цель/узкий сценарий; новый визуальный мир не нужен.

## Запуск

Node>=24.15<25, без npm-зависимостей.

```sh
WORK_ADMIN_USER=admin WORK_ADMIN_PASSWORD='<your-local-secret>' npm start
npm test
```

По умолчанию http://127.0.0.1:8852, база .data/workspace.sqlite. PUBLIC_ORIGIN, DATABASE_PATH, PORT и HOST задаются явно; не публикуйте базу и пароли. Сервер не публичный. HTTP требует cookie/Origin/CSRF. Первый admin создаётся из env, сотрудников добавляет admin.

[20 тестов](docs/test-output.txt), [проверка](docs/verification.json), [браузерные доказательства](docs/browser-proof.json), [официальный референс](docs/reference-audit.md). Реальные full-page снимки пока только1280CSS: resize capability не применилась; мобильная проверка не заявлена. Нет полного внешнего аудита безопасности/нагрузки/touch/screenreader.
